## What was done

- **Error analysis of baseline v0** (dev holdout, 27.7k S1, 0.9682; F0.5 gained if the bucket were fixed):

  | bucket | pairs | gain |
  |---|---|---|
  | true pair below the threshold | 3,600 | +0.0131 |
  | true pair not a candidate (blocking) | 2,334 | +0.0092 |
  | look-alike accepted (the record is an orphan) | 470 | +0.0048 |
  | record given to the wrong S1 | 513 | +0.0046 |
  | true pair lost to another S1 by ownership | 298 | +0.0012 |

  Indic-name S1 (30% of India S1) scored 0.923 against 0.975 and carried 29.5% of the loss: the baseline features
  fold Indic names to empty strings.
- **Blocking misses (full holdout, v0):** 47,111 of 1,901,267 true pairs (2.48%), 66% India; 41.7% have an
  Indic-script record name, 23.7% an empty record address with a typo'd name.
- **Features v1** (`feats.py`, 73 features; 12 min train, 15 min test):
  - Indic names transliterated; on Indic-script names the transliterated legal forms are dropped and an
    Indic -> Latin token dictionary is applied: 693 entries learned from true pairs of **train folds 5-19 only**
    (tek -> tech, kanstrakshan -> construction, eksaports -> exports);
  - typo-tolerant name matching (edit distance 1, or 2 from 6 letters): unmatched IDF mass, max and count per side,
    and the number of substituted tokens (a swapped first name is not a typo);
  - skeleton and skeleton-prefix overlaps, concatenated-name scores (domains, hashtags);
  - number relations over whole number sets (the S1's first number among the record's numbers is now the top
    feature by gain);
  - per-country IDF; NaN rapidfuzz scores on empty sides; `ber.features.context` groups + record-side rivalry.
- **Stage 0 + 1** (`s1.py`): a 200-tree filter keeps 17.6-17.9% of pairs and 99.95% of true pairs (test keeps the
  same share); three OOF XGBoost models (depth 9, eta 0.06, about 2,100 trees each); holdout and test get their mean.
  Stage-1 probabilities are already calibrated on the holdout (bins within about 0.01).
- **Stage 2** (`s2.py`): rivalry features over the full candidate graph (per record: best, second, margin, rank,
  claims above 0.5, share; per S1: rank, max, sum, counts above 0.5/0.8/0.95, neighbour gaps, same-source sums),
  p1 and the top-30 stage-1 features, OOF over the same groups; isotonic on OOF p2 of training folds only.
- **Decision** (`decide.py`): argmax ownership, then the exact expected F0.5 per S1 (Poisson binomial over the
  S1's other candidates; checked against brute force on 300 random cases) vs one global threshold.
- **G3 per-token distractor encoding** (`feats_lo.py`): out-of-fold log-odds of a true match when a name word is
  extra or missing in close training pairs. It rediscovered the look-alike vocabulary: holdings -9.8, group -9.7,
  industries, enterprises, ventures, public, exports, overseas (about -8.6), north/south/east/west/valley/harbor/
  metro (about -7.6); benign: OCR'd legal forms (c0mpany, lnc), doing/known/as/fka/formerly.
- **G9 cluster support** (`cluster.py`): similarity of the record to the S1's other confident records.
- **Blocking v1** (`ber.block`): `indic.name_tokens` (legal forms dropped, dictionary applied) and character
  4-grams of names in `name_short` (params `indic_dict`, `ns_ngrams`).
- **Tools:** `buckets.py` (full-holdout loss buckets), `rules.py` (decision rules tuned on holdout folds 0-1, scored
  on 2-4), `variant.py` (test matches for a decision variant), `france_check.py`, `FastEval` (vectorized macro
  F0.5, identical to `ber.eval.metric`).
- **`(number, street)` key fix** (`ber.features.context.numstreet_keys`): the key took the first address word,
  which in France is the street type ("32 Rue André Maginot" -> 32|r; about 450 S1 per key on test, far outside
  the training range) and the state on reordered records. It now takes the first word after the house number,
  skipping street types, articles and house markers. Not in v2's features yet (v3).

## How to reproduce or continue (exact commands)

```
# env: BER_WORK_DIR / BER_DATA_DIR / BER_OUTPUT_DIR when running from a worktree; PYTHONPATH = src + model-v1
python -m ber.pipeline --stage block --split train --tag ameya-block-v1 --set trim_s1=15 --set trim_r=4 --set indic_dict=ameya-fx1 --set ns_ngrams=4 --set dev_tag=ameya-block-v1-dev
python -m ber.pipeline --stage evaluate --split train --tag ameya-block-v1
python -m ber.pipeline --stage block --split test --tag ameya-block-v1 --set trim_s1=15 --set trim_r=4 --set indic_dict=ameya-fx1 --set ns_ngrams=4
cd experiments/ameya/model-v1
python feats.py --cands ameya-block-v1 --split train --tag ameya-fx2
python feats_lo.py --feats ameya-fx2 --split train
python feats.py --cands ameya-block-v1 --split test --tag ameya-fx2
python feats_lo.py --feats ameya-fx2 --split test
python s1.py --feats ameya-fx2 --tag ameya-s1-v2 --groups str,cx,lo
python s2.py --feats ameya-fx2 --s1 ameya-s1-v2 --tag ameya-s2-v2 --groups str,cx,lo --cluster
python decide.py --scores ameya-s2-v2 --col pc --tag ameya-model-v2 --base ameya-model-v1
python -m ber.pipeline --stage write --split test --tag ameya-model-v2 --in candidates=ameya-block-v1 --in matches=ameya-model-v2
python student_resource/utils/validate_submission.py --matching output/matching_results.tsv --candidate output/candidate_pairs.tsv --test-dir student_resource/dataset/test --check-ids
```
(`ameya-fx1` / model v1 is the same chain on `ameya-block-v0` without `feats_lo` and `--cluster`.)
